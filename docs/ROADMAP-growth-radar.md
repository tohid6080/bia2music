# نقشه‌ی راه: رشد کانال + رادار موسیقی ترند (معماری و وابستگی‌ها)

> وضعیت: **همه‌ی مراحل ۶ تا ۱۰ پیاده و تست شدند.** (آداپتورهای مرحله ۸ با داده‌ی واقعی آزموده نشده‌اند؛ هر منبع «🧪 آزمایش» دارد.) هر مرحله جداگانه پیاده، تست و گزارش می‌شود و **بعد از هر مرحله متوقف می‌شوم تا تأیید بدهید.**

## ۰. اصول ثابت (در همه‌ی مراحل)
- **هیچ انتشار خودکاری**؛ رسیدن به نقطه‌ی رشد، پیشنهاد رادار، یا گزارش روزانه هیچ‌چیزی منتشر نمی‌کند. انتشار فقط همان مسیر موجود (پیش‌نمایش ← تأیید ← تأیید نهایی).
- **هیچ API پولی**. کلیدهای رایگان فقط از `.env` و فقط با موافقت شما.
- **ممنوع و در طراحی ممکن نشده:** خرید عضو، حساب جعلی، عضویت اجباری، پیام انبوه، افزودن بدون رضایت. ربات هیچ ابزاری برای این‌ها ندارد (نه ارسال به فهرست کاربران، نه join اجباری).
- **صداقت داده:** کلیک/بازدید را نمی‌شمارد و «۰» یا «تخمین» نشان نمی‌دهد؛ می‌نویسد «در دسترس نیست». رتبه/تاریخ/آمار حدس زده نمی‌شود. داده‌ی قدیمی با برچسب «به‌روز نیست» نشان داده می‌شود.
- همه‌چیز فقط برای ADMIN_USER_ID و از داخل ربات.

## ۱. قابلیت اول: «📈 رشد و توسعه کانال»

### ۱.۱ واقعیت‌های فنی تلگرام (و آنچه مطمئن نیستم)
| موضوع | وضعیت |
|---|---|
| ساخت لینک دعوت با نام (`createChatInviteLink`, `name`) | ممکن؛ ربات باید ادمین با حق **Invite Users** باشد |
| تعداد اعضا (`getChatMemberCount`) | ممکن (همین الان استفاده می‌شود) |
| **تعداد کلیک روی لینک** | **در Bot API وجود ندارد.** نمایش نمی‌دهیم و صریح اعلام می‌کنیم |
| **تعداد عضو هر لینک** | Bot API عدد نمی‌دهد؛ فقط از رویداد `chat_member` (فیلد `invite_link`) قابل شمارش است |
| رویداد `chat_member` برای **کانال** | **باید عملاً آزمایش شود.** مستندات می‌گویند ربات ادمین باید `chat_member` را در `allowed_updates` بخواهد؛ اما اینکه تلگرام این رویداد را برای ورود/خروج مشترکین **کانال** (نه گروه) و با چه پایداری/تأخیری می‌فرستد، تأیید نکرده‌ام |
| عضویت از جست‌وجو/نام عمومی کانال | رویداد بدون `invite_link` ← «منبع نامشخص/ارگانیک» |
| خروج اعضا | رویداد خروج لینک ندارد؛ فقط اگر قبلاً ورود همان کاربر ثبت شده باشد به کمپین نسبت داده می‌شود |
| بازدید پست | Bot API نمی‌دهد (همان محدودیتی که قبلاً گفتم) |

**قدم صفر مرحله‌ی ۶: «آزمون قابلیت»** — ربات (با موافقت شما) چند دقیقه رویدادها را ثبت می‌کند و با یک عضوگیری آزمایشی نتیجه را گزارش می‌دهد: «رویداد ورود دریافت شد / نشد»، «لینک دعوت در رویداد بود / نبود». اگر داده نیامد، تمام گزارش‌های مبتنی بر رویداد با پیام صریح «داده‌ی عضویت در دسترس نیست» نشان داده می‌شود و فقط شمارنده‌ی اعضا (روزانه) می‌ماند.

### ۱.۲ داده و حریم خصوصی (حداقل ذخیره)
- شمارنده‌های **تجمیعی**: ورود/خروج روزانه به تفکیک کمپین (بدون هویت).
- برای نسبت‌دادن «خروج» به کمپین (بازماندگی) یک **هش نمکی یک‌طرفه** از شناسه‌ی کاربر نگه می‌دارم، نه خود شناسه و نه نام/نام‌کاربری. قابل خاموش‌کردن است. (**تصمیم لازم از شما**، بخش ۶)
- هیچ پیامی به اعضای جدید فرستاده نمی‌شود.

### ۱.۳ اجزا
| جزء | کار |
|---|---|
| `growth/campaigns.py` | ساخت/ویرایش/آرشیو کمپین (اینستاگرام، واتساپ، دوستان، کانال همکار، گروه موسیقی، تبلیغات، سایر)، ساخت لینک با نام، ابطال لینک |

| `growth/reports.py` | اعضای فعلی، رشد امروز/هفته/ماه، ورود/خروج روزانه، بهترین کمپین، نمودار (گسترش `reports.py` موجود) |
| `growth/texts.py` | تولید متن تبلیغ با قالب‌های رایگان (بخش ۲) |

### ۱.۴ جدول‌های جدید (مهاجرت v6)
`growth_campaigns(id, name, source_kind, invite_link, link_name, created_at, status, notes)`،
`member_events_daily(day, campaign_id|NULL, joins, leaves)`،
`member_hashes(hash, campaign_id, joined_day)` (اختیاری)،
`growth_texts(id, kind, text, edited, updated_at)`،
`milestones(id, members, title, note)`.
(`member_snapshots` و `daily_metrics` فعلی دوباره استفاده می‌شوند.)

### ۱.۵ تولید متن (بدون AI پولی)
قالب‌های قابل ویرایش برای: واتساپ، اینستاگرام، تلگرام، همکاری با کانال‌ها، پیام کوتاه دعوت، معرفی آهنگ‌های محبوب/ترند (از آرشیو واقعی ربات). متغیرها: لینک کمپین، تعداد آهنگ‌های آرشیو، محبوب‌ترین‌ها. با قالب‌های چندگانه + انتخاب تصادفی. هر متن در `<code>` برای کپی با یک لمس و دکمه‌ی «✏️ ویرایش». اگر بعداً AI را روشن کنید می‌تواند بازنویسی کند (اختیاری، با همان محافظ هزینه‌ی فعلی).

### ۱.۶ برنامه‌ی هفتگی (قانون‌محور، نه ادعای قطعی)
ورودی: روند اعضا، علایق تجمیعی، پسندها، واکنش‌های پست، ترکیب آرشیو، تعداد انتشار هفته‌ی قبل، درخواست‌های کاربران. خروجی: نوع موسیقی پیشنهادی، تعداد پست، روز/ساعت‌های **آزمایشی** (نه «بهترین»)، موضوع نظرسنجی، کانال‌های همکاری برای **بررسی**، محتوای اشتراک‌پذیر. همه با عبارت «پیشنهاد؛ نتیجه تضمین‌شده نیست». **محدودیت صادقانه:** چون بازدید پست در دسترس نیست، ارزیابی ساعت انتشار فقط با واکنش‌ها و تعامل ربات ممکن است و داده‌ی کم (۲۲ عضو) معنی‌دار نیست؛ این را صریح می‌نویسد.

## ۲. قابلیت دوم: «🔥 رادار موسیقی‌های ترند»

### ۲.۱ معماری عمومی (آداپتور منبع)
هر منبع یک کلاس با قرارداد ثابت است:
```
ChartSource:  id, name, region(s), license_note, terms_url, min_interval,
              fetch(region, kind) -> [ChartEntry(rank, title, artist, url, native_score?, published_at?, genre?, country)]
```
- **کش** در دیتابیس (`chart_snapshots`) با TTL هر منبع؛ **محدودیت نرخ** و ثبت خطا؛ خطای یک منبع بقیه را متوقف نمی‌کند.
- **robots.txt** و شرایط هر منبع قبل از اولین استفاده بررسی و در ربات نمایش داده می‌شود؛ **هر منبع فقط بعد از «تأیید صریح مدیر» فعال می‌شود** (پیش‌فرض خاموش).
- هیچ دورزدن محدودیت، ورود/لاگین، یا استخراج از صفحه‌ی ممنوع‌شده. منبعی که مجاز نباشد ← فقط «لینک قابل مشاهده» + «ثبت دستی».
- هر ردیف همیشه با **منبع، لینک منبع، زمان دریافت** نمایش داده می‌شود؛ بیش از TTL ← «⚠️ به‌روز نیست».

### ۲.۲ بررسی منابع (وضعیت واقعی)
| منبع | نتیجه بررسی | روش پیشنهادی |
|---|---|---|
| **FarsiChart** (`farsichart.com/music/trending`) | **تأیید نشد.** این محیط ابری به آن دسترسی ندارد، پس robots/شرایط را نخواندم | قبل از پیاده‌سازی: شما لینک شرایط را در ربات می‌بینید؛ ربات robots.txt را در لحظه می‌خواند؛ فقط با تأیید شما و در صورت مجازبودن فعال می‌شود. وگرنه «لینک + ثبت دستی» |
| **Radio Javan** | API عمومی رسمی نمی‌شناسم | لینک + ثبت دستی (مگر منبع رسمی/فید مجاز پیدا شود) |
| **YouTube Trending Music** | API رسمی `videos.list` با `chart=mostPopular`، دسته‌ی موسیقی و `regionCode` (کلید رایگان گوگل؛ هزینه‌ی هر درخواست ۱ واحد از سهمیه‌ی پیش‌فرض ۱۰٬۰۰۰ واحد در روز ← **تأییدشده در مستندات/منابع جستجو** برای هزینه و سهمیه؛ پارامترهای chart در جستجو تأیید نشد و در آزمون مرحله‌ی ۸ باید دیده شود؛ ممکن است برای برخی کشورها (مثلاً ایران) داده ندهد) | API رسمی با کلید رایگان شما |
| **YouTube Music Charts / Shorts Charts** (صفحات charts.youtube.com) | API رسمی نمی‌شناسم | فقط لینک + ثبت دستی (اسکرپ نمی‌کنم) |
| **Spotify Charts / Shazam Charts** | صفحات نمودار نیازمند ورود/بدون API عمومی رایگان رسمی (از دانسته‌ی خودم؛ تأیید نشده) | فقط لینک + ثبت دستی |
| **Last.fm** (`chart.getTopTracks`, `geo.getTopTracks`) | **وجود endpointها تأیید شد** (فقط کلید API رایگان، بدون ورود کاربر؛ خطای محدودیت نرخ دارد). شرایط استفاده (غیرتجاری/نمایش منبع) را **نخوانده‌ام** و باید قبل از فعال‌سازی بخوانم | کلید رایگان شما؛ داده‌ی کشوری شامل «Iran» ممکن است کم باشد |
| سایر منابع عمومی/رسمی احتمالی برای نمودار خارجی (فید رسمی اپل، API عمومی Deezer، MusicBrainz برای اطلاعات پایه) | **از دانسته‌ی خودم، تأیید نشده** | در مرحله‌ی ۸ شرایط هرکدام را بخوانم، سپس فقط مجازها اضافه شوند |

**نتیجه‌ی صادقانه:** منابع خارجی رسمی و رایگان وجود دارد؛ ولی **برای موسیقی ایرانی هیچ API رسمی که مطمئن باشم نمی‌شناسم.** بخش ایرانی رادار در عمل متکی است بر: FarsiChart (اگر مجاز باشد)، Last.fm/YouTube (اگر داده‌ی ایران بدهند) و **ثبت دستی/لینک منبع**. این را قبل از وعده‌دادن می‌گویم.

### ۲.۳ جدول‌های جدید
`chart_sources(id, name, enabled, approved_at, terms_url, min_interval_s, last_fetch_at, last_status, last_error)`،
`chart_snapshots(id, source_id, region, kind, fetched_at, ok)`،
`chart_entries(snapshot_id, rank, title, artist, url, native_score, published_at, genre, country, title_norm, artist_norm)`،
`radar_suggestions(id, key_norm UNIQUE, title, artist, first_seen_at, status[new|saved|archived|drafted|rejected], license_status[unknown|link_only|official_link|licensed_by_admin], license_note, song_id NULL)`،
`radar_settings` (در `bot_settings` موجود).

### ۲.۴ امتیاز «داغ بودن» (شفاف و جدا از امتیاز رسمی)
- **اگر منبع شاخص خودش دارد** (رتبه/امتیاز) همان **بدون تغییر** با برچسب «رسمی منبع» نمایش داده می‌شود.
- **امتیاز داخلی ربات** (برچسب جدا: «امتیاز ربات»؛ قابل توضیح در یک صفحه): ترکیب خطی از  
  رتبه‌ی فعلی (هرچه بالاتر بهتر)، **تغییر رتبه نسبت به عکس قبلی همان منبع** (فقط اگر عکس قبلی در بازه‌ی معقول موجود باشد)، **حضور در چند منبع مستقل** (جایزه‌ی هر منبع اضافه)، **تازگی** (فقط وقتی تاریخ انتشار را خود منبع داده؛ وگرنه صفر و «نامشخص»).  
  وزن‌ها در ربات نمایش داده می‌شوند و قابل تنظیم‌اند. «سرعت رشد بازدید» فقط برای منبعی که **خودش دو مقدار پشت‌سرهم** می‌دهد؛ بقیه «در دسترس نیست».
- اگر داده‌ی قبلی نباشد: «تغییر رتبه: نامشخص» (نه ۰).

### ۲.۵ فیلتر و دسته‌ها
دکمه‌ای: ایرانی/خارجی، کشور نمودار، سبک، زبان، بازه‌ی زمانی، تازه/ترند، پرطرفدار، بیشترین رشد. گروه‌ها: ترند امروز، ترند ایرانی، ترند خارجی، تازه‌ها، سریع‌ترین رشد، خوانندگان پرطرفدار (شمارش حضور در نمودارها)، بر اساس سبک (سبک فقط اگر منبع بدهد؛ وگرنه نامشخص).

### ۲.۶ چرخه‌ی پیشنهاد تا انتشار
دکمه‌ها: ⭐ ذخیره، 📚 افزودن به آرشیو، 📝 آماده‌سازی کپشن، 🔎 منبع اصلی، ✅ پیش‌نویس انتشار، ❌ رد.
- **تکراری نشدن:** مقایسه با آرشیو و پیشنهادهای قبلی با همان نرمال‌سازی فارسی موجود (`title_norm/artist_norm`) و رد/ذخیره‌های قبلی.
- **فایل:** رادار فقط **متادیتا و لینک رسمی** می‌دهد. «افزودن به آرشیو/پیش‌نویس» یک رکورد **بدون فایل** می‌سازد؛ فایل را شما با مجوز خودتان می‌فرستید و به همان رکورد وصل می‌شود. ربات **هیچ فایلی دانلود یا منتشر نمی‌کند**.
- **مجوز:** برای هر پیشنهاد `license_status` پیش‌فرض «نامشخص» است؛ فقط شما می‌توانید به «با مجوز» تغییرش دهید (با یادداشت). متن کارت می‌گوید فایل از کجا و با چه مجوزی قابل تهیه است یا «نامشخص».
- انتشار: همان مسیر امن موجود؛ هیچ مسیر خودکاری اضافه نمی‌شود.

### ۲.۷ گزارش روزانه
ساعت قابل تنظیم (پیش‌فرض خاموش)، فقط به چت شما: بخش ایرانی و خارجی، نام/خواننده/منبع و رتبه/تغییر رتبه/کشور/لینک، شامل تازه‌ها و پرشتاب‌ها، با «آخرین به‌روزرسانی». خطای منبع ← در گزارش «این منبع امروز در دسترس نبود»، بقیه ادامه می‌یابند.

## ۳. نقاط عطف رشد (قابل تغییر)
جدول `milestones` با مقادیر اولیه: ۲۲ شروع/آزمایش محتوا، ۱۰۰ بررسی اولیه‌ی علایق، ۵۰۰ توسعه‌ی برنامه و تنوع، ۱۰۰۰ تحلیل جدی‌تر. ویرایش/افزودن/حذف از ⚙️ تنظیمات. رسیدن به هر نقطه فقط **تغییر متن پیشنهاد برنامه و تعداد/تنوع پیشنهادهای رادار** است؛ **هرگز انتشار یا ارسال خودکار.** رادار از همان روز اول و برای هر تعداد عضو فعال است.

| کلید رایگان **Last.fm** | ترند خارجی/کشوری | پس از خواندن شرایط |

## ۵. مراحل (هر کدام جدا، تست‌شده، و توقف برای تأیید شما)
1. **مرحله ۶ — پایه‌ی رشد:** آزمون قابلیت `chat_member`؛ کمپین‌ها و لینک نام‌دار؛ QR؛ شمارش ورود/خروج و منبع؛ گزارش‌های رشد و نمودار؛ پیام‌های صریح محدودیت (کلیک ندارد، داده‌ی ناموجود).
2. **مرحله ۷ — محتوا و برنامه:** تولید متن‌های تبلیغ (قابل ویرایش/کپی)، برنامه‌ی هفتگی (قابل تنظیم)، نقاط عطف.
3. **مرحله ۸ — هسته‌ی رادار و منابع:** چارچوب آداپتور، کش و سقف نرخ، بررسی robots/شرایط و تأیید منبع توسط شما، آداپتور منابع مجاز، لینک و ثبت دستی برای بقیه، امتیاز شفاف، نمایش «آخرین به‌روزرسانی».
4. **مرحله ۹ — رادار تا انتشار:** گروه‌ها و فیلترها، دکمه‌های پیشنهاد، تکراری‌نشدن، وضعیت مجوز، گزارش روزانه، اتصال به آرشیو/کپشن/پیش‌نویس.
5. **مرحله ۱۰ — اتصال رشد به محتوا:** استراتژی بر اساس نقاط عطف و آمار واقعی (فقط پیشنهاد).

## ۶. تصمیم‌ها (مدیر اختیار را به صلاحدید من سپرد؛ تصمیم‌های گرفته‌شده)
1. **هش نمکی:** پیش‌فرض **خاموش** (کمترین اطلاعات شخصی)؛ با دکمه‌ی تأییددار قابل روشن‌کردن؛ با خروج عضو پاک می‌شود.
2. **QR:** با `segno` (پایتون خالص، اختیاری).
3. **کلید YouTube/Last.fm:** در مرحله‌ی ۸؛ فعلاً لازم نیست.
4. **FarsiChart:** تا بررسی شرایط، فقط «لینک + ثبت دستی».
5. **ترتیب:** ۶ ← ۷ ← ۸ ← ۹ ← ۱۰ (مراحل ۶ تا ۱۰ تمام شد). تعریف مرحله‌ی رشد: اولین نقطه‌ی عطف (۲۲) = مرحله‌ی ۰؛ هر نقطه‌ی بعدی یک مرحله بالاتر.
