# اجرای ربات قبلی (musicbot) بدون Termux و بدون روشن‌بودن گوشی

ربات برای کار کردن باید جایی همیشه‌روشن اجرا شود؛ «بدون Termux» یعنی آن «جا» یک سرویس ابری باشد. شما سرویس رایگان با خواب را انتخاب کردید. این راهنما برای **Render (Free Web Service)** نوشته شده است، چون مستندات رسمی‌اش را بررسی کردم. **این مسیر را روی Render واقعی آزمایش نکرده‌ام**؛ فقط کد و تست‌های محلی انجام شده است. نام دکمه‌های سایت ممکن است کمی فرق کند.

## قبل از شروع، این‌ها را بدانید (مستندات رسمی Render: [Deploy for Free](https://render.com/docs/free) و [FAQ](https://render.com/docs/faq))
- سرویس رایگان بعد از **۱۵ دقیقه بدون درخواست می‌خوابد** و با اولین درخواست بعدی حدود **یک دقیقه** طول می‌کشد تا بیدار شود. یعنی اولین پیامی که بعد از خواب به ربات می‌دهید با تأخیر جواب می‌گیرد (تلگرام دوباره تلاش می‌کند).
- **دیسک موقت است:** با هر خواب، ری‌استارت یا استقرار، فایل‌های محلی (دیتابیس SQLite) **پاک می‌شود**.
- سقف **۷۵۰ ساعت رایگان در ماه**؛ با رسیدن به سقف، سرویس‌های رایگان تا ماه بعد معلق می‌شوند.
- وقتی سرویس خواب است، **زمان‌بند ربات کار نمی‌کند** (مثلاً گزارش روزانه‌ی ساعت ۹:۳۰ یا یادآور انتشار). این کارها با بیدارشدن بعدی انجام می‌شوند. انتشار همچنان فقط با تأیید خودتان است.
- شرایط پلن رایگان را Render می‌تواند تغییر دهد.

## چطور دیتابیس از پاک‌شدن در امان می‌ماند؟
ربات هر ≥۱۰ دقیقه بعد از تغییر، و هنگام خاموش‌شدن، یک فایل پشتیبان **فقط برای خودتان** می‌فرستد و آن را **پین** می‌کند (پیام قدیمی پاک می‌شود). وقتی سرویس بیدار می‌شود و دیتابیس نیست، همان فایل پین‌شده را می‌خواند و بازیابی می‌کند. هیچ سرویس بیرونی لازم نیست.
**محدودیت صادقانه:** تغییرات بعد از آخرین پشتیبان (کمتر از ~۱۰ دقیقه) اگر میزبان ناگهانی قطع شود ممکن است از دست برود. پیام پین‌شده‌ی چت ربات را **پاک یا آن‌پین نکنید** (و چت را حذف نکنید). این بازیابی را روی تلگرام واقعی آزمایش نکرده‌ام.
اگر این ریسک برایتان قابل‌قبول نیست، یک VPS ارزان (چند دلار در ماه) با دیسک دائمی امن‌تر است.

## مراحل (همه از گوشی)
1. **انتقال دیتابیس فعلی (اگر داده دارید):** در ربات روی Termux: ⚙️ تنظیمات ← 💾 پشتیبان‌گیری. فایل در چت می‌آید؛ روی آن پیام **نگه دارید ← Pin**. (اگر داده‌ای ندارید این مرحله را رد کنید.)
2. **ربات Termux را متوقف کنید** (Ctrl+C). دو برنامه با یک توکن نباید هم‌زمان کار کنند.
3. در [render.com](https://render.com) حساب بسازید ← **New ← Web Service** ← مخزن GitHub `tohid6080/bia2music` را وصل کنید.
4. نوع اجرا: **Docker** (فایل `Dockerfile` در ریشه‌ی مخزن است). Instance Type: **Free**.
5. در بخش **Environment** این متغیرها را وارد کنید (توکن را فقط اینجا بگذارید، نه در GitHub یا چت):

| نام | مقدار |
|---|---|
| `TELEGRAM_BOT_TOKEN` | توکن ربات (از BotFather؛ بهتر است توکن را تازه کنید) |
| `ADMIN_USER_ID` | `76040678` |
| `CHANNEL_ID` | `@bia2music1395` |
| `TIMEZONE` | `Asia/Tehran` |
| `WEBHOOK_URL` | بعد از اولین استقرار، آدرس سرویس (مثل `https://نام-شما.onrender.com`) |

6. سرویس را بسازید. آدرسش را از بالای صفحه‌ی سرویس کپی کنید، در `WEBHOOK_URL` بگذارید و **Manual Deploy ← Deploy latest commit** بزنید.
7. در لاگ‌ها باید `Webhook mode` و `restore check: restored` (یا `none` اگر پشتیبانی نبود) ببینید. سپس در تلگرام /start بزنید (اگر ربات خواب بود حدود یک دقیقه صبر کنید).

## نکته‌ها
- برای اینکه ربات «همیشه بیدار» بماند، پلن رایگان کافی نیست. من عمداً ابزار «پینگ دائمی برای بیدار نگه‌داشتن» نگذاشته‌ام، چون ممکن است خلاف شرایط سرویس باشد.
- اگر `ADMIN_USER_ID` و توکن درست باشد ولی پشتیبان پیدا نشد، در لاگ `restore check: none` می‌بینید؛ یعنی دیتابیس تازه ساخته شده است. در آن صورت فایل پشتیبان قبلی را دوباره Pin کنید و سرویس را ری‌استارت کنید.
- برای جلوگیری از افشای توکن: فایل `.env` هرگز در Git یا ایمیج Docker نیست (`.dockerignore`).
